## Goal

Create a small read-only **Approved Documents Registry**.

It discovers reviewed HTML candidates inside one configured local directory and validates a selected candidate as a Stage 2 compatible reviewed-HTML v1 input.

This task does not execute lexical extraction. It only creates the reliable document-selection boundary that U2.2 will use.

## Controlled folder layout

The registry root is an explicit caller-supplied `Path`, never a hard-coded machine-specific location.

A candidate has exactly this relative layout:

```text
<approved-documents-root>/
  <job_id>/
    <review_revision_id>/
      document.html
```

An optional sibling `review.json` may exist, but U2.1 must neither require, parse, nor modify it.

The folder is the initial operational eligibility rule. Do not introduce a second Stage 1 approval check, a new document lifecycle, or any approval action.

## Required behavior

Add one small module under `src/app/extraction_review/`, for example `approved_documents.py`.

It must provide:

1. Deterministic, paginated discovery of correctly laid-out `document.html` candidates below the supplied root.
   - Return lightweight path/layout metadata only.
   - Do not load or parse every HTML artifact while listing.
   - Use a small explicit page size maximum.
   - Do not build a database, index, cache, registry file, or persisted state.

2. Selection of one candidate by its root-relative identity: `job_id` plus `review_revision_id`.
   - Resolve paths safely.
   - Reject traversal, absolute-path substitution, symlink escape, missing files, and malformed folder layout.
   - Never write to the approved-documents directory.

3. Stage 2 compatibility validation for the selected `document.html`.
   - Reuse the existing Stage 2 reviewed-HTML reader; do not implement a second HTML parser.
   - Consume the reader as a stream and discard yielded pages. Do not use an API that materializes all pages.
   - Return the reader’s validated `ReviewedHtmlV1Input`, including its exact HTML-byte SHA-256.
   - Require its root `job_id` and `review_revision_id` to match the two folder components.
   - Preserve and surface a clear structured U2.1 selection/validation error when the Stage 2 reader rejects the file.

4. Return one compact selected-document value containing only:
   - root-relative document identity;
   - resolved read-only HTML path;
   - validated `ReviewedHtmlV1Input`.

Do not create a separate Stage 3 source hash. Keep Stage 1 `document_hash` distinct and optional, as in U1.

## Tests

Add focused tests covering:

- deterministic discovery and pagination of correctly laid-out candidates;
- directories/files that do not match the layout are excluded;
- successful selection returns the existing reader’s validated HTML provenance and SHA-256;
- folder `job_id` or `review_revision_id` mismatch with HTML root provenance is rejected;
- malformed HTML is rejected through the selection boundary;
- missing file, path traversal, and symlink escape are rejected;
- listing does not parse or load HTML files;
- U2.1 creates no files under the approved-documents root and no persistent registry/index.

Use synthetic small reviewed-HTML fixtures consistent with the existing lexical HTML-reader tests. Do not use or alter real local user documents.
