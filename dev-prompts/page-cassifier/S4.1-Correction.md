## Defect 1 — Normalize entities exactly once

The current implementation uses `HTMLParser(convert_charrefs=True)` to decode page-readable text, then `normalize_evidence_text()` calls `html.unescape()` again. This can perform an unintended second entity decode and violates the locked rule:

> Normalize only by HTML-entity decoding and whitespace collapsing.

Correct the implementation so that evidence comparison performs **exactly one HTML-entity decoding pass per compared representation**, followed only by whitespace collapsing.

Required invariants:

- Scripts, styles, and comments remain excluded from readable evidence.
- Original page HTML fragments remain unchanged.
- No case folding, Unicode normalization, fuzzy matching, OCR repair, translation, paraphrase, or distant-text splicing.
- The same normalization semantics apply to page text, element text, and quote text.
- Do not silently repair a mismatch.
- Preserve the existing public purpose of `normalize_evidence_text()` or replace it with small, clearly named helpers only if that makes the one-decode rule explicit and testable.

Add focused tests covering:

- Ordinary entity matching such as `A&amp;B`.
- A double-encoded boundary such as `A&amp;amp;B`, proving a second decode does **not** occur.
- Entity handling combined with whitespace collapse.
- The existing Unicode, table-cell, quote-present, and quote-absent behavior.

## Defect 2 — Source validation must not be bypassable

The current `merge_page_classification(...)` accepts an optional caller-provided `SourceEvidenceValidation` and checks only its page binding. A caller can therefore supply incomplete or falsely verified validation and obtain a completed/excluded result without all returned evidence being checked.

Source-aware evidence validation is mandatory and automatic. Correct this boundary.

Required behavior:

- `merge_page_classification(...)` must always use source validation that covers every evidence item from every structurally valid call outcome.
- Prefer the smallest safe design: remove the public optional `source_validation` argument and have merge calculate it from the prepared page and ordered outcomes.
- If retaining any supplied validation value is necessary, it must be internal-only and must be verified as an exact, complete, binding-matched representation of all valid outcome evidence. It must be impossible to omit an item, alter its result, or claim no unverified evidence.
- `validate_source_evidence(...)` must require exactly one outcome for each fixed call ID `1`, `2`, and `3`, with no duplicate or missing slot.
- Keep the existing semantics:
  - Structurally valid but source-unverified evidence preserves the label/evidence, requires review, and blocks exclusion.
  - Missing, failed, or invalid calls make the page incomplete and preserve valid findings as provisional.
  - No label/evidence fabrication or silent dropping.

Add focused tests that prove:

- A caller cannot bypass a source mismatch by supplying an empty, incomplete, or falsely verified source-validation object.
- Duplicate/missing call slots are rejected by source validation and merge.
- Normal completed/excluded behavior still works when every evidence item has been automatically checked.
- Existing incomplete and source-mismatch behavior remains intact.

## Defect 3 — Exact original page-fragment binding must not use string searching

The current `_slice_page_fragment()` searches source text for a literal `id="..."`, then uses string searching for `<section`. This is not a reliable binding to the parsed `section.page` element:

- It does not support valid single-quoted attributes.
- It can be fooled by matching text in comments, scripts, or unrelated markup before the real page section.
- It risks returning the wrong original fragment even though readable text was derived from another page.

Replace this with a small robust mechanism that identifies the **exact source span** of each `section.page` recognized for page preparation and returns that original byte/text substring.

Required invariants:

- The returned fragment is the complete original enclosing `section.page` fragment for the same prepared page number and page HTML ID.
- Preserve original source formatting, comments, scripts, styles, attributes, and descendants in that fragment.
- Correctly handle valid single-quoted and double-quoted attributes.
- Do not locate a page by an `id` string that merely appears in comments, scripts, text content, or another element.
- Correctly handle nested `section` elements while finding the matching close tag.
- Continue to reject absent or ambiguous page identity and duplicate page-local HTML IDs.
- Do not introduce a third-party HTML parser or dependency.
- Do not revalidate/re-hash the full document per page; preparation remains once per document and prepared-page lookup remains pure.

A small scanner/token-span helper in `page_input.py` is appropriate if needed. Keep it private and narrowly scoped.

Add focused tests covering:

- A single-quoted page `id`.
- A comment or script before a page containing text such as `id="source-page-1"` that must not hijack fragment selection.
- Nested section content retained within the correct outer page fragment.
- The original comments/scripts/styles remain in the selected page fragment while still excluded from readable evidence.
- Existing multi-page isolation and lookup behavior.
