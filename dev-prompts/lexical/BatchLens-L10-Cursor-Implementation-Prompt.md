## Deliverable and contracts

Add a small, fixed V1 unit/value capability with a clear **per-block or bounded block-stream API** usable by the later L12 runner. Keep parameter-name mentions on the already accepted L05→L07→L08 dictionary path (`Component.PARAMETER_NAMES`); demonstrate that this path works without selecting or detecting equipment. Do not build a second parameter search engine or an end-to-end runner in L10.

Use the L01 `UnitMention`/`UnitOccurrence`, `ValueExpression` variants, `ValueOccurrence`, and `BlockEvidence`/`CharSpan` contracts. Every occurrence must retain exact original text and zero-based, half-open Unicode code-point offsets; nested number/unit/group spans must agree with the original block. A unit mention has its own evidence and no parameter, equipment, material, or operation identity. A parsed value/unit grouping is syntactic only. Preserve repeated occurrences and alternative source references without multiplying one textual hit merely because denormalized equipment rows repeat. `equipment.Unit` is an eligible unit vocabulary from L05, not a parameter or equipment mention. Include a small fixed, versioned vocabulary for common material quantity units and tightly controlled categorical/cue rules; equipment units alone do not cover quantities. Keep original spelling and controlled unit spelling/identity distinct. If L01 unit provenance cannot represent repeated source rows, make only the smallest backward-compatible additive contract change, with a focused regression, analogous to L08's supporting-row references. Do not silently drop source references or invent catalogue identities.

Support these **independent** cases:

| Block text | Required evidence |
|---|---|
| `Impeller speed` | Parameter-name dictionary mention when selected; no filled unit/value/equipment detection. |
| `rpm` | Unit mention when selected; no parameter name/id or equipment detection. |
| `120 rpm` and `120rpm` | Original-span scalar-with-unit expression; independent unit mention if `units` was selected. |
| `Impeller speed: 120 rpm` | Parameter-name mention and value/unit evidence, with no semantic link between them. |
| `2.5 kg`, `20–25 °C`, `< 2.0%`, `100 ± 5 g` | Controlled scalar/range/comparison/tolerance forms as applicable. |
| Fixed categorical terms such as `OFF` or `under vacuum`, and an explicit cue such as `Speed: 120` | Emit only when a documented, narrow V1 rule applies; no inferred entity or unit. |

The shared value parser runs only for selected `quantity_expressions` and/or `parameter_value_expressions`. A direct request for either value component may internally recognize a unit without selecting the `units` output component; do not emit a standalone `UnitOccurrence` unless `units` is selected. If both value components are selected and one expression is eligible for both, emit it once with both `applies_to` values. No mandatory parent, value, or unit is implied by a `_with_` preset. Preserve overlaps where they describe different evidence, while avoiding duplicate identical expressions from competing grammar rules. Keep ambiguous `1,000` unresolved or unparsed; never silently choose thousands versus decimal. Preserve exact decimal spelling, including `1.10`. Reject obvious page numbers, dates, identifiers, and step labels as free-standing quantities. No unit conversion, catalogue `Published range` substitution, plausibility correction, cross-cell binding, or material/equipment/parameter associations.

Use existing L06 normalization and boundary semantics, including atomic-unit continuation (`rpm/min`, `min⁻¹`, `mL·min⁻¹`, `kg²` must not yield shorter false-positive units). Reuse the L07 unit raw-discovery capability and L05 unit terms where it fits, but do **not** feed units into L08: its `UNEXPECTED_UNIT_DISCOVERY` boundary remains valid. A small unit-specific adapter/aggregation in L10 is acceptable. Avoid a generic regex/search framework, a new user-selectable profile, or a parallel catalogue engine. The rules are fixed V1 implementation data, not a new execution-config switch. Keep memory bounded by the existing finite L02 limits and the small vocabularies; do not retain an entire document or unbounded result list.

**Resource clarification carried forward:** shard limits are explicit finite configuration values. No production component needs access to physical RAM to choose a shard size. Host RAM inventory is optional diagnostic context; do not add automatic hardware-adaptive sizing, privileged hardware queries, or a requirement for such access. A process/container limit, when provided by deployment, is the relevant operational budget. L09's 32 GiB was a declared benchmark budget on that machine, not an engine requirement or a default for all hosts.
