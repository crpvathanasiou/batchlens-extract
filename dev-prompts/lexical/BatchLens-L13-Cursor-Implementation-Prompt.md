## Streamed result contract

Create a **new run directory under `output.directory`** keyed by the L12 run ID; never replace an earlier run or touch the input/snapshot. Write one versioned, UTF-8 JSON evidence artifact for each **completed component**. The published structure must let a reader traverse run/document → physical pages → source blocks → matches, retaining empty pages/blocks, original block text, `node_id`, source/OCR references, exact code-point spans, overlaps, all ambiguous candidates and `supporting_row_ids`. Component selection and `not_requested`, completed-zero, failed, and partial states must be unambiguous. Preserve L01 model serialization semantics and deterministic content/order for pinned inputs apart from run ID/timing. A compact per-component artifact plus a final run manifest is acceptable; document its schema and a simple way for a later UI to locate a hit by page/node/span. Keep source candidates in the machine-readable artifact; do not design the end-user presentation now.

L12 emits component-scoped page skeletons before its block stream. Stage/reassemble these records with bounded memory (temporary files in the same run filesystem are fine) so each published page owns its blocks; do **not** retain the whole document or all blocks in RAM. Validate page/block ownership, ordering, and completeness before calling a component artifact complete. Uncommitted component files are provisional. `abort_component` discards its provisional output while leaving already committed siblings intact. A component with zero hits still publishes its complete page/block coverage. Keep output serialization errors explicit rather than silently truncating or dropping evidence.

## Publication transaction and manifest

Keep the L12 sink lifecycle intact: `complete_component` commits only that component; `complete_run` seals the sink but **cannot yet write the final manifest**, because the runner has not returned its `LexicalRunResult`. A thin orchestration function/CLI should call the runner, then finalize publication from the returned result. Require sink-sealed state, matching run ID and component outcomes/artifacts, no `run_error`, and no outstanding provisional component before finalization. A pre-validation failure or run-level sink/finalization failure must not produce a final manifest claiming publication. Do not fabricate validated input metadata on those paths.

Publish completed component artifacts via temporary files and atomic same-filesystem replacement, then write the **final manifest last**, also via temporary file and atomic replacement. Flush and use appropriate file synchronization where supported; do not overclaim crash durability on platforms that cannot provide it. The final manifest must be self-describing and versioned, carry validated HTML identity and producer metadata, knowledge snapshot identity, effective configuration and rules digests, engine/dependency versions, requested presets/components, resolved components, fuzzy selection, L12 per-component and overall outcomes/errors, compact measured monitoring, artifact relative paths/byte sizes/SHA-256, and an L01-compatible completed `PublicationRecord`/manifest claim. Include safe run status and explicit error codes; do not include uncontrolled log text. Never hash the manifest as though its own bytes were already known.

An extraction with one or more completed components and isolated failed components may publish **partial**: the final manifest says extraction `partial`, publication `completed`, lists only completed component artifacts, and preserves failed component outcomes. An all-failed extraction may have a truthful final outcome manifest only if the runner cleanly sealed and all manifest requirements can be met; it must claim no completed component evidence. If component output fails, treat that component as failed, discard its provisional artifact, and publish a partial run only if remaining completed artifacts and manifest can safely be published. If artifact finalization, serialization, rename, hash, or manifest publication fails or is interrupted, do **not** leave a final manifest that claims completed publication; any stranded temporary or component files are not a published run. Preserve earlier runs. No resume, retry, background cleanup service, or cross-process run registry in V1.

Provide a small reader/verification helper or documented schema sufficient for tests and subsequent UI work to load the final manifest, verify referenced artifact hashes, and enumerate page/block/match evidence without rebuilding the entire run in memory. Do not turn this into a review UI or a new API.
