## Locked Stage 3 MVP model

Stage 3 stores one **current** extraction-review state per document:

- read-only source HTML and Stage 2 provenance;
- the complete current findings list;
- one `current_revision_id`, used only for stale Save conflict detection;
- `approval: null` or one current final extraction-result approval.

The U1.1 contracts and pure transitions already implement this model.

There is no Stage 3 revision history, version list, revision folders, approval ledger, delta chain, parent revision link, retry ledger, SQLite database, or generic persistence framework.

A later effective Save replaces the current state and clears its approval. Older content and approval are intentionally discarded.

## Required implementation

Add a small local JSON store for the complete `ExtractionReviewState`.

Use this exact on-disk shape:

```text
<data-dir>/
  extraction-reviews/
    <workspace-key>/
      current-review.json
```

`workspace-key` must be a deterministic, filesystem-safe SHA-256 hex value derived solely from the Stage 3 document identity (`job_id`). Do not use an unsanitized identifier as a path.

`current-review.json` is the only Stage 3 persisted state file. It contains the full current `ExtractionReviewState` serialized as JSON.

Implement a small, explicit store/service in `src/app/extraction_review/`. Keep it proportionate: one public class or module is sufficient.

It must support:

1. Create a new current state for a document.
   - Write one `current-review.json`.
   - Refuse to overwrite an already existing current state.

2. Load the current state for a document.
   - Parse and validate it through `ExtractionReviewState`.
   - Return an explicit not-found result/error when no current file exists.

3. Save edits.
   - Load current state.
   - Call the existing pure `save_review_edits(...)` transition.
   - Write the new full state only when the transition outcome is `changed`.
   - On conflict, validation error, or unchanged result, do not alter file bytes.

4. Approve extraction result.
   - Load current state.
   - Call the existing pure `approve_extraction_result(...)` transition.
   - Write the new full state only when the transition outcome is `changed`.
   - On conflict, validation error, or unchanged result, do not alter file bytes.

5. Reload/restart recovery.
   - A new store instance using the same data directory must load the latest saved or approved state.

Use atomic replacement for successful writes: write a sibling temporary file, flush it, then replace `current-review.json`. Do not leave temporary files after a successful write.

This is a single-local-process store. Do not add inter-process locks, a worker, queues, retry receipts, or a concurrency framework. The existing revision token remains the stale-write protection within this scope.
